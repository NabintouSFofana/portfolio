Full-Stack Build · 2024 — Present Lead developer · live brand

Schicgirl™ 🌿

The bilingual (FR/EN) natural-hair brand I build and maintain end-to-end — a dozen-plus live pages for Type 4 hair, each with its own admin dashboard, from storefront to AI assistant.

  • Full-stack developer
  • 12+ live pages
  • Anthropic Claude API
  • Bilingual · FR / EN
  • Supabase
  • Google Apps Script
  • Admin dashboards
  • Vanilla JS · no build step

Built — I'm the full-stack developer behind Schicgirl™, a bilingual natural-hair brand for Type 4 hair. I design, build, and maintain the whole product surface — the link-in-bio hub, sales pages, customer tools, and the admin dashboard behind nearly every one of them. It's all hand-written HTML/CSS/JS with no build step, served from GitHub Pages, and wired to Supabase and Google Apps Script where it needs real persistence.

Shipped tools —

  • CoilCare AI™ Conversational Type 4 hair assistant on the Anthropic Claude API, client-side key.
  • HydraCheck Hydration/porosity diagnostic with a full leads dashboard.
  • SchicChat Bilingual diagnostic chatbot, leads backed by Google Sheets.
  • Link-in-bio hub A conversion-ladder homepage with a visual content editor and click/visit analytics.
  • Booking + reviews Consultation flow with admin dashboard; Supabase-backed reviews that surface on the hub.
  • Freebie funnel Lead-magnet landing, subscriber dashboard, and self-hosted bilingual PDF delivery.
  • Sales pages & affiliate site Six ebook pages plus a porosity-sorted Amazon mini-site with its own editor.

Learned — Almost everything I know about shipping software end-to-end, I learned here: two languages, a real LLM API, admin tooling that gets used daily, and the discipline of supporting something that's live. Building for a real, active community is the fastest feedback loop I've found.

Project 02 · 2025 — 2026 Team of 6 · v2 refactor solo

Math Adventure 🧮

A class-built math practice site for K–5 students — and a solo rebuild that gave it a new design and a cleaner backend.

  • HTML · CSS · JS
  • Java Spring Boot
  • REST API
  • JUnit · MockMvc
  • Full-stack
  • Team of 6 → solo v2

Built — A K–5 math practice site for our Software Engineering course. Six of us, one semester. Spring Boot back-end, vanilla JS front-end, all served from one process.

Refactor — I came back solo and rebuilt the spine. Static controllers became Spring services with DI; plain-string responses became JSON DTOs with real HTTP codes; a 635-line front-end file became eight ES modules; the test suite grew from 30 to 50 cases. New look too — italic display type, chunky shadows, an animated fox coach.

Learned — Working with five other people taught me more than the code did — merge conflicts, code review, picking up someone else's half-finished feature. The solo rebuild taught me a different thing: code is much easier to change when each piece does one job.

Project 04 · 2026

Caesar Cipher 🔐

The classic shift cipher, visualized — write a message, drag the shift slider, watch the alphabet wheel rotate, and see all 26 possible decryptions at once.

  • Java
  • JavaScript
  • HTML
  • CSS
  • Algorithms
  • Cryptography
  • SVG
  • Interactive UI

Built — Started as a Java implementation for class — algorithm, edge cases, tests — and grew into a web demo with an interactive alphabet wheel that rotates as you drag the shift. The newest piece is a cipher breaker that shows all 26 decryptions at once. Caesar is easy to crack; seeing all 26 lined up makes that obvious.

Learned — Two things. Writing the same algorithm in Java and then JavaScript made me notice how differently they think about strings. And the SVG wheel was harder than the cipher — five lines of math, an afternoon of SVG. Worth it: the wheel is what people remember.

Personal Finance Tracker 💸

A Java Swing app that takes its UI seriously — modern flat theming, stats sidebar, and a quiet warning when an expense looks unusual.

  • Java
  • Swing
  • FlatLaf
  • OOP
  • Desktop
  • Editorial palette

Built — A Java desktop app for tracking income, expenses, and a monthly savings goal. FlatLaf gave it a modern look in the same cream-and-rust palette as this portfolio. Sidebar with balance, income, expenses, a progress bar, and a small safety net: if a single expense tops 30% of total income, the app pauses to confirm.

Learned — Keeping logic out of the UI. My first version had the stats math inside the methods that drew the labels — worked, but couldn't be reused. I moved it into the Account class and wrote a CLI version that shared the same logic. That "it just works in two places" moment is what made it stick.

Project 06 · 2026

InsightFlow 📊

A small data tool — Flask web app for instant CSV dashboards, plus a Python CLI for one-page PDF reports. Two interfaces, same cleaning and insights core.

  • Python
  • Flask
  • Pandas
  • HTML
  • CSS
  • Matplotlib
  • FPDF
  • Data Analytics
  • Dashboard

Built — A small data tool with two faces. The Flask web app takes a CSV upload and returns a dashboard with metric cards, anomaly flags, and a cleaned preview. The Python CLI produces a one-page PDF you'd actually email to someone. Both share the same cleaning and insights modules.

Learned — Writing the CLI was the fun part. Making it useful was harder. v1 dumped a wall of numbers, v2 tried to "summarize" but said nothing real. v3 picks a few specific things worth pointing out and leaves the rest in the data. Small distinction, changed how the whole tool feels. Splitting the code into shared modules also taught me a lot — the CLI and the web app pull from the same cleaner.py and insights.py.

Project 07 · 2025

JobBoard 💼

A small, fast job listing that reads like newspaper classifieds — not SaaS cards on a coloured gradient.

  • HTML
  • CSS
  • Vanilla JS
  • localStorage
  • Editorial design

Built — A two-page job board: listings with search, dynamic location/type filters, save button per row; bookmarks page with a live counter in the nav. Numbered classifieds rows instead of SaaS cards — you can scan twenty listings without scrolling. While building, I caught a quiet bug: one job id appeared twice in the JSON, which flagged both copies when you saved one. Fixed.

Learned — Tech was straightforward — fetch, localStorage, debounced search. The surprise was layout. Cards-on-grid felt cluttered at twenty listings. Switching to newspaper-style numbered rows let me show three times more on one screen. Some design problems already have an answer; you just have to stop reaching for the default.

  • CSS
  • Vanilla JS
  • localStorage
  • Per-user storage
  • Dark mode
  • UX-led

Built — A to-do app I built because I wanted to use it. Project 10 · 2025

Weather App ☀️

A weather app with a big italic temperature, a 24-hour forecast strip, and a security lesson I learned the hard way.

  • Vanilla JS
  • OpenWeather API
  • Geolocation
  • BYO API key
  • Custom SVG icons

Built — A modern weather app: city search, geolocation, °C/°F toggle (computed locally), six-stat grid, 24-hour forecast strip pulled via Promise.all. Custom SVG icons for every OpenWeather code with day/night variants. Uses a bring-your-own-key pattern — your OpenWeather key lives only in your localStorage, never on my server.

Learned — Technically: fetch, Promise.all, navigator.geolocation, three real error states instead of one generic "something went wrong." The bigger lesson came from v1, though: I committed my OpenWeather API key to a public GitHub repo. Anyone could have used it. I revoked it immediately and rebuilt around BYO-key. Slightly more friction for the user, but I can't make the mistake twice.
