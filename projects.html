01 / Freelance development · 2024–present

Schicgirl

A bilingual platform, maintained in production.

JavaScript · Supabase / PostgreSQL · HTML / CSS

Visit the site ↗Source ↗

The problem

A bilingual natural-hair brand needs a storefront, diagnostic and booking tools, and a membership experience that connects its forum and lesson library.

My contribution

I build and maintain the web platform, including an 11-table Supabase/PostgreSQL schema with row-level security and subscription checks. One account connects the site, forum, and interactive studio.

Engineering decisions

I addressed expired sessions that incorrectly denied returning members access by adding token refresh and a single retry on unauthorized requests. I also standardized stored form values across French and English to prevent mismatches and accidental overwrites.

Current status

The public site is live; the forum and studio require membership. The points ledger is still client-authoritative. Moving it to PostgreSQL is the next step before using points for rewards.

02 / Private product · 2026

NABIELA notes

Lecture notes and computer science diagrams in one workspace.

JavaScript · IndexedDB · Canvas · Windows launchers

Discuss this project ↗

The problem

I wanted a notebook for my university coursework that supports technical notation and diagrams using a keyboard and trackpad. NABIELA brings lecture capture, course folders, and editable study drawings into the same workspace.

My contribution

I define the workflows, guide AI-assisted implementation, review behavior, and refine the interface. The app brings together lecture capture, editable study diagrams, flashcards, and Word export.

Engineering decisions

Notes and images live in IndexedDB. Autosave waits for transaction completion and retries failed writes; bounded recovery snapshots and JSON/folder backups provide recovery options. Each generated diagram retains its structured source so it can be edited again after restoring a backup.

Current status

A private product in development for a future commercial release. This portfolio provides an overview; app downloads, installers, and source code are not distributed here.

03 / Team project + solo refactor · 2025–2026

Math Adventure

A class project I came back to improve.

Java · Spring Boot · JUnit / MockMvc · JavaScript

Source ↗

The problem

Our six-person Software Engineering team built a math practice application for K–5 students. After the course, I returned to improve its maintainability and API behavior.

My contribution

In the solo rebuild, I moved static utility logic into Spring services with dependency injection, replaced plain-text responses with JSON DTOs and appropriate HTTP status codes, and split the frontend into eight ES modules.

Engineering decisions

I separated responsibilities so changes could be tested and made independently. The rebuild expanded the JUnit test suite; the original team project also gave me experience with code review, merge conflicts, and shared ownership.

Current status

Course project with a subsequent solo rebuild. The repository provides the implementation and setup instructions.

04 / Independent data tool · 2026

InsightFlow

From a messy CSV to a clearer view.

Python · Flask · Pandas · Matplotlib

Try the web app ↗Source ↗

The problem

A CSV full of missing values, duplicates, and unusual observations can be hard to interpret. InsightFlow provides a quick cleaning and exploration workflow.

My contribution

I built a Flask app that accepts CSV uploads and displays metric cards, anomaly flags, and a cleaned preview. A companion CLI creates a one-page PDF with summary statistics, charts, and plain-English insights.

Engineering decisions

I refactored the initial script into shared cleaner, insights, and reporter modules. The web app and CLI reuse the same core, while presenting results in a format suited to each interface.

Current status

The web app is deployed on Render. The repository includes the CLI and shared modules.

05 / Computer Graphics team project · 2026

TerraScape

Procedural geometry, with a clearly defined contribution.

C# · Unity · L-systems · Git

Source ↗

The problem

Our Computer Graphics team built an interactive terrain sandbox. My scope focused on placing objects, generating fractal geometry, and helping the team collaborate in Unity.

My contribution

I implemented raycast-based object placement and runtime manipulation, plus an L-system grammar and recursive turtle-graphics interpreter for trees and space-filling curves. Teammates owned the terrain, water, and camera systems.

Engineering decisions

I established repository structure, a Unity-specific ignore file, branch conventions, and onboarding documentation to reduce scene-file conflicts. I also wrote the final technical report and coordinated delivery.

Current status

Completed course project. The repository contains the team implementation; the work described here identifies my own scope.
